# Integrated native v3 metadata engine: inactive trial candidate

This supersedes only the unimplemented wiring section of the earlier native catalog plan. Older prototype files remain frozen historical proposals. No actual Ops `scripts/`, workflow, environment, key, repository snapshot or live backup unit was modified.

Run `build-native-engine.proposed.py <existing reviewed scripts directory> <NEW private engine-copy directory>` only to generate an inactive engine. It copies the actual planner/deriver source, preserves the original metadata batch as `hourly_metadata_batch_legacy.py`, generates the protected-before-derive and scoped-rule changes, installs the proposed new batch inside THAT COPY, and generates the optional native-catalog v3 validator branch. Existing source anchors must match; an existing output directory is refused. No module import performs cloud IO.

The integrated batch performs one default-locked native `restore --verify` of exactly four allowlisted v3 JSON paths. Authenticated delivery contents select schema3; tags do not classify format. For a non-v3 or undeclared delivery, the original five-file legacy fetch/manifest validator/checkpoint behavior runs with default native locks. UNKNOWN requests still return the actual archived manifest via default-locked dump. No synthesized outer manifest is returned.

After exact native restore succeeds and all selected-file path/size/JSON/seal bindings validate, the batch records an in-memory `(repository/scope binding, snapshot, exact seal path, bytes, SHA)` origin. Native catalog verification now REQUIRES this origin callback, including for multiblob seals. A correctly sized seal without the receipt fails; another snapshot or changed bytes fail. The receipt is private code-established state, not accepted from arbitrary JSON. One-point eviction clears the previous point's origins.

Native CLI callbacks use fixed `restic cat tree SID:exactPGpath`, then `cat blob ID` ONLY for reached authenticated child TreeIDs; RAW ID/hash checks remain mandatory. No content data blob is fetched by cat. Unseen multi-blob PG file identities still require exact-snapshot native dump of the real full outer once. Reused ordered content IDs plus size can share an authenticated digest only within this private job. Base/marker WAL reads and all original timeline/continuity/base-restore checks remain. No physical replay is claimed.

Bounds: existing180s derivation deadline; <=35s per native read and <=40s restore; <=8MiB per selected JSON/tree; four initial files per point; <=256MiB aggregate selected batch JSON; <=512MiB aggregate native catalog/dump output; <=4096native reader processes; <=512 cached native trees/16MiB; <=20,000native PG rows/content-hash cache. Existing 20MiB compressed marker-WAL bound stays separate. Timeout/cancellation signals only its own restic child with SIGINT, waits up to8s for lock cleanup, then KILL/reap up to5s only if necessary. Cleanup grace may extend wall time beyond admission deadline; no blanket unlock is used.

Twelve Linux synthetic tests pass against generated actual-engine source APIs: four-path locked selection; original legacy manifest fallback; UNKNOWN actual-manifest access; same-snapshot multiblob seal origin acceptance; missing/cross-snapshot/tampered origin rejection; bad delivery/seal SHA; bounded locked CLI; SIGINT/reap on timeout; actual derive→new batch→catalog→actual planner closure; generated audit wiring; and existing v3/legacy validation paths. Earlier18tests remain applicable. These synthetic callbacks do not constitute an actual B2 or performance result.
