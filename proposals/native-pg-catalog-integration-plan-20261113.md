# Bounded native PG catalog prototype and integration boundary

This is code-only, not activated. Deployed Ops scripts, policy, workflows, secrets, B2 contents and default native reader locks are unchanged. No new retention horizon or deletion permission is implied.

`native-pg-catalog-authentication.proposed.py` authenticates the exact native PG subtree. Its callbacks must use checksum-pinned restic0.16.4, exact authorized immutable snapshot/path, **default locked** `cat tree snapshot:/hourly/root/postgres-selfcontained`, then `cat blob ID` for ONLY reached child subtree IDs. The latter RAW bytes must SHA-256-match that authenticated ID before parsing or caching. No data-blob ID is passed to cat blob. Catalog traversal never visits uploads/media or the full outer application manifest. Cache is private in-process, repository/scope bound, <=512trees/16MiB/20,000rows; deadline is preserved. Cross-job/public caches are absent.

A single native content-blob ID equals the SHA-256 of that entire single-blob file. Empty files have the empty digest and no content IDs. Multiple ordered blob IDs do **not** equal a whole-file SHA. An unseen multi-blob file therefore requires an exact same-snapshot, native-dump authenticated full outer manifest and the existing outer↔sealed-PG row equality before seeding the private cache. Subsequent byte-identical `(size, ordered blob IDs)` can reuse that established digest; new/reordered content cannot. Seed claims retain the existing producer-manifest metadata trust boundary and do not become physical replay evidence. Native namespace must exactly equal sealed PG rows plus the seal itself. This checks actual native file presence and size as well as metadata. No arbitrary `verified:true` or caller-supplied manifest establishes a seed: native callback plumbing is part of the remaining required review.

`retention-safety-candidate.py::v3_catalog_candidate` generates a minimal branch against the **actual** current `hourly_selfcontained_v3.derive_v3`. A trusted exact-snapshot native dump callable may attach a reviewed `native_pg_catalog` callback. The resulting evidence has a distinct `native-PG-catalog-content-identity-v1` scheme and catalog digest. It never labels synthetic projection bytes as the archived outer manifest. Without the callback the original full-outer validation branch remains unchanged. Base manifest accepted-restore hash, base EndLSN/timeline, contiguous WAL, exact marker segment and decompressed named marker checks all continue. Physical replay remains false.

Ten Linux synthetic tests pass (0.227s): single-blob direct validation with no outer read; shared native subtree caching; unseen multi-blob fallback; exact ordered-content reuse; changed chunk order refusal; missing payload refusal; same-size substitution refusal; raw-tree SHA refusal; seal substitution refusal; malicious seed rejection; scope/deadline guards; and executing actual patched derive_v3 while preserving its marker-WAL fingerprint rejection. These are synthetic authenticated callback fixtures, **not** an actual B2 performance or native PostgreSQL acceptance. The separate safety candidate has eight passing tests.

Smallest integration steps, not yet implemented/activated:

1. Keep current exact protected-to-KEEP-before-derive change and conservative hourly/PITR rules. Review against the newly installed native-reader sources instead of overwriting them with an older copy.
2. Add bounded default-locked native callback plumbing to the real audit's existing subprocess/deadline/ephemeral environment. Return RAW native tree bytes; use exact fixed scope paths and authenticated subtree IDs only. All multi-command reads remain inside the approved immutable-point hold and external concurrency contract.
3. Change the metadata batch's initial selection to the four small v3 JSON files (capture, marker, delivery, PG seal). Select delivery schema by authenticated contents, never by tag. Legacy/UNKNOWN retains the exact existing full-manifest path. New v3 native mode authenticates those four selected files directly through native restore and the reviewed catalog; it must not run the old batch validator that unconditionally fetches outer. This step is necessary: attaching a callback alone would leave existing five-file network cost unchanged.
4. Wire native catalog proof into actual derivation; on an unseen multi-blob identity fetch that point's full outer once, validate all original seal bindings, and seed. Fail closed on any conflict, unsupported node, bound or deadline. Keep legacy/UNKNOWN/ASOF and restored-parent checks unchanged.
5. First actual readonly trial must record bytes, unique native trees, initial outer fallbacks and elapsed time, at growing retained volume. Unique changed multi-blob files can still force repeated outer reads; this prototype makes no worst-case720-point/180-second guarantee. Default old full validation is the fallback, not a reason to relax checks or silently approve a shorter horizon. No nonzero maintenance until the complete integrated actual engine and protections pass external admission.

No new owner decision is needed for the code-only correctness work. A shorter hourly/PITR deletion horizon, cross-job receipt storage, new signer/secret or paid execution would require a separate explicit decision; none is used here.
